# Security model

## Trust boundaries

Trusted extension contexts include the Side Panel, Settings page, and MV3 service worker. Web pages, injected page results, bookmark titles and URLs, model output, WebMCP definitions, WebMCP results, GitHub repository responses, and imported skill metadata and bodies are untrusted.

`chrome.storage.local` is restricted to `TRUSTED_CONTEXTS`. API keys and OAuth values never enter runtime messages, the service worker, injected functions, model messages, tool results, IndexedDB sessions, or logs. Diagnostic strings pass through credential redaction.

## Authentication

Provider setup requires an explicit user gesture. API-key prompts are provider-owned, and Pi Browser Agent stores their result under only that provider ID. OpenAI Codex login requests its two authentication origins and validates device-flow response shapes and the ChatGPT account claim. Polling handles pending, slowdown, denial, local or server expiry, and cancellation. Automatic refresh runs inside the credential store's cross-context serialized mutation, and a rotated refresh token replaces the old credential in one storage write.

Credential removal first aborts the agent, waits for it to become idle, then removes only the selected provider credential. Before each run, Chrome asks for the selected model endpoint's exact origin. Requests cannot silently switch providers or hosts after auth failure.

## Current-tab controls

- Chat, provider authentication, and individually confirmed bookmark reads work without a readable tab. Only the active, accessible HTTP(S) tab in the focused Chrome window is targeted by page tools. A no-page turn keeps those tools disabled even if the active tab changes; queued instructions cannot upgrade it.
- The UI capability label is not authorization: known restricted origins, local files, and apparent PDFs are excluded before binding; the worker probes document type and scriptability before page reads, WebMCP, picker, screenshots, tab metadata/navigation, and persistence of context-menu selection text, so extensionless PDF viewers also fail closed. Chrome-denied injection marks a web tab unavailable until reload/navigation. The worker still checks visibility and epoch; page tools also require exact-origin approval. The explicit context-menu gesture does not grant page-tool access. File/PDF page reads and general file import are not implemented. The separate Skills picker reads only a user-selected `SKILL.md`; it grants no page-tool or general filesystem access.
- Tab and window activation automatically update the target; unsupported pages clear it. UI-only page status (bounded title and kind) changes even between two unsupported tabs; protected URLs and file paths are not sent to the model by default.
- Tab ID, URL, and context epoch identify the operation context.
- Navigation or a visible-tab change after request creation causes `STALE_CONTEXT`.
- Ordinary host access is approved from an explicit user gesture and scoped to selected exact origins in trusted extension storage. The worker requires both that app-level approval and Chrome host permission.
- Screenshot capture separately requests optional `<all_urls>` from its confirmation gesture because Chrome requires it when `activeTab` is no longer live. Although Chrome treats that grant as satisfying narrower host checks, Pi Browser Agent does not add exact app approvals from it. The worker still captures only the active visible HTTP(S) viewport and rechecks the grant before each capture.
- Password and file inputs are always denied.
- Form submissions and downloads always prompt. Cross-origin links/navigation, bookmark reads, tab switching/opening, and WebMCP calls require a confirmation or a matching, mode-scoped prior approval. Strict asks every time; Balanced remembers until Chrome restarts; Convenient keeps the approval until cleared. Only the same operation and exact target/arguments match. Changing modes clears previous approvals; no approval overrides Chrome's native permissions or runtime checks.
- Cross-origin navigation additionally requires destination host permission. User-confirmed opening of a new web tab is separate from agent navigation; the exact search destination URL must be approved before it goes to the search provider (a previously approved exact URL may match in Balanced or Convenient). Page access after opening still requires exact-origin approval.
- Tools accept fixed schemas; injected code cannot evaluate model-provided JavaScript.

Mutation tools declare `replay: "never"` and execute sequentially. Interrupted sessions do not continue automatically.

The user-driven element picker is not a mutation capability. The worker binds one random token to the exact active tab context for at most one minute and accepts results only from the extension's top-frame sender. Target navigation invalidates pending startup, including same-URL reload; unrelated background-tab navigation does not. Exact-site approval, sender/frame/token checks, expiry, and stale-context checks remain required.

The viewport shield is a manual non-modal top-layer popover inside the active top-frame light-DOM modal, or under `html` otherwise. Important styles, computed ancestor zoom, and an owned-surface geometry probe protect its geometry without changing page layout or page-owned top-layer state. Its 1% black painted background is required for compositor input routing over out-of-process iframes; a fully transparent region can be omitted. Startup takes top-frame keyboard focus and waits for two animation frames. Cleanup releases the paint wait; early results are acknowledged before the startup reply completes. Target and visible-text hit tests filter the shield from `document.elementsFromPoint()` without ever disabling interception.
- The shield receives pointer/click/context/drag activation instead of the target and blocks keyboard activation in the top frame.
- A later child-document focus transfer, new modal/popover, fullscreen change, or lost shield protection stops selection with a fixed local retry/reload error. Errors contain no page content, URL, or raw exception. Normal `Esc`, repeated toggle, and navigation cancellation stay quiet.
- Cleanup is idempotent across selection, cancellation, target navigation, tab/window focus change, timeout, Side Panel close, and worker restart. It restores prior page focus only if the shield still owns focus.
- A page-level capture listener registered earlier can still observe an intercepted event. This is an extension overlay, not browser-internal input isolation.

Picker extraction is bounded to five composer items, 8 KB per context, and 16 KB combined. It reads top-frame light DOM only. Selecting over an iframe captures only its top-frame wrapper, never child-document content; shadow-owned controls remain unsupported. Field values, editable text, password/file data, hidden text, full HTML, and credential-bearing URLs are excluded. The worker validates exact keys, scalar limits, geometry, sender, token, page URL, and context freshness before the panel receives a chip. The selected JSON enters only a user message under an explicit untrusted-data header. Saved selectors and rectangles are untrusted relocation hints and never bypass normal mutation discovery and revalidation. No permission, dependency, or persistent storage change is required. No newer `currentCSSZoom` API is required, and the declared Chrome 116 minimum is unchanged. Isolated picker checks do not establish full-extension compatibility; see the known minimum-version baseline limitation in [manual acceptance](manual-acceptance.md#element-picker-reliability--2026-10-23).

Element discovery uses the same approved-origin and visible-tab checks as ordinary page reads. It exposes only bounded control and scroll-container descriptions, not field values, editable contents, hidden text, full HTML, or sensitive password/file targets. Descriptions are untrusted model input. Short references require an accompanying random snapshot ID; a reference is not a capability to bypass permission, confirmation, or target checks. Actual nodes live only in the extension's isolated world, not page attributes. Worker metadata expires after five minutes and is invalidated on new discovery, navigation, activation/focus changes, and restart. Detached/replaced nodes and changed action metadata fail closed, including changes to resolved submit override URLs, effective submit form identity, submitter name/value, and encoding/validation overrides through direct, label, or nested targets. Submitter payload metadata stays in the isolated-world fingerprint for comparison; it is not returned to the model or persisted, and no editable field values are read. Discovery and reference-based mutations reject ancestor-only hit tests, including controls fully clipped by overflow ancestors, and zero-opacity CSS filter functions on targets or their filtering ancestors. Filter checks on slotted light-DOM controls follow exposed assigned slots and shadow hosts, including nested slot assignments; they do not enumerate shadow-owned controls or expose closed-root slot assignments. Boxless `display: contents` ancestors do not apply their own filters and are skipped. Active modal, popover, and fullscreen roots are checked, including roots inside shadow trees, but filters on their outside filtering ancestors are not applied to top-layer content. Name collection applies the same filter check, starting at each directly slotted text node's exposed assigned slot rather than skipping to its parent host. Parent visibility and text-range hit checks remain required; changed filtered names invalidate reference fingerprints, including after focus handlers. Serialized computed filters longer than 4,096 UTF-16 units are rejected before parsing, rather than partially inspected or assumed visible, including during final mutation and post-focus checks. This bounds parser input, not browser style computation; arbitrary SVG filter effects are not evaluated. Final mutation assertions recheck cancellation, host access, snapshot freshness, and the visible context; typing also rechecks after focus handlers run, with a fresh filter cache. Filter decisions are shared only within a synchronous validation phase, never across operations or the focus-handler boundary. Once an injected mutation reports success, snapshot invalidation caused by that mutation does not retroactively report it as rejected. Read results and deferred navigation authorization still require snapshot freshness; failed or unknown operations are not assumed successful or replayed.

Browser scrolling accepts only a direction, page/half-page/bounded-pixel amount, and an optional discovered container reference. It runs a fixed instant DOM scroll, requires approved site access and the final visible-target assertion, and needs no action confirmation. Successful scrolling deletes all discovery references, including at boundaries. Native option selection accepts only a discovered single select and one exact value or label. Every selection requires fresh confirmation because input/change handlers can submit or navigate; no remembered approval applies. Disabled/ambiguous options fail closed, and option metadata changes invalidate references before a confirmed change. Success also invalidates all discovery references. Element details return bounded names, roles, state, geometry, and scrollability, never field values or HTML. All three tools use strict worker schemas and existing site-access checks. Page scroll/input/change handlers can still react to these fixed operations; they are not arbitrary-code tools. Native keyboard and hover operations remain unavailable. See [browser interaction tools](browser-interactions.md).

Filtered discovery preserves the same traversal, visibility, fingerprint, and snapshot boundaries. Exact role/type filters and literal name matching cannot expand the first 2,000-node scan; every page replaces references. Text search is literal and case-sensitive with no code or regular expressions. It scans at most 2,000 Text nodes/100,000 source UTF-16 units, including excluded text, and returns at most 50 bounded matches within 48 KB. It excludes editable/sensitive/hidden/clipped content, does not scroll, and returns no mutation references. Raw source offsets are temporary descriptions, not stable identities or authorization. Effective editable state, including `document.designMode`, is excluded. Non-default CSS `clip`, `clip-path`, and mask images on box-generating ancestors exclude text conservatively; arbitrary shapes are not evaluated. Hidden content visibility is excluded. Overflow checks use client/padding geometry through exposed slot ancestry and independently clipping body containers. Rounded clips and rotated/skewed/flipped/3D transforms fail closed. Boxless ancestors do not apply box-dependent rendering effects; effective visibility respects descendant overrides. Scope validation does not enumerate full-subtree Range geometry.

Condition waits bind to one original document context. The worker polls read-only probes every 250 ms, defaults to 5,000 ms, caps at 10,000 ms, and rechecks permission, readability, current context, and cancellation. Abortable delays end with the request. Context changes fail closed, including a quick switch away and back or same-URL reload between probes; a timeout is `TIMEOUT`, not injection denial. Context-free runtime waits capture the original active context once. No page observer, injected sleep, custom interval, or model-defined code is accepted. Search and waits neither replace nor renew snapshots.

Native option-catalog reads are a narrow label-only exception to the form-content exclusion. A fresh visible single-select reference authorizes up to 50 entries within 48 KB; catalogs above 2,000 options are rejected. Returned fields are label, index, effective disabled flag, and label-truncation flag. Hidden options and options in hidden groups are excluded by hidden/ARIA-hidden and computed display, visibility, opacity, and filter metadata; these metadata also enter fingerprint checks. Option pagination uses native indices, not returned-entry counts. Raw option values, selected flags, selected value, and selected index are excluded. Labels above the 256-unit selection bound are marked truncated. Catalog changes fail fingerprint validation; reads do not invalidate references or authorize another catalog. Labels and snippets remain untrusted model data and can contain page instructions.

Native checkbox/radio changes require fresh confirmation for every actual change in all modes; no reusable approval applies. Radio deselection and ARIA-only controls are unsupported. A supported already-matching state sends no events, needs no prompt, and keeps references. After confirmation, state, radio-group identity, node, metadata, visibility, access, context, and cancellation are rechecked before one native DOM activation. Private checkbox/radio payload values enter approval comparison but never tool output. Radio groups bind actual member identities and states; incomplete 2,000-element group scans reject activation. All references are invalidated after activation, even if a handler cancels or reverses the state. Handlers can submit, remove the target, or navigate. Removal/navigation can make the final state unverified after execution; never reinterpret this as a safe-to-retry rejection. Inspect current state before a new user-authorized action. No checked setter plus second activation, automatic replay, or native-input permission is added.

## Target-reference and clarification controls

Pair roles bind distinct submitted attachment IDs, not list positions, selectors, or model-selected URLs. The runtime validates image positions and nested selected-element context against the actual submitted arrays. Pair metadata, context, and wrapper overhead share one 16 KiB UTF-8 budget; no independent second allowance applies. Task text is required for pairs. Extracted page fields stay explicitly untrusted. None of these data enters the system channel or grants a mutation capability. References from another page require already attached raster images, not background-tab reads or arbitrary URL fetches.

`request_user_input` is a local AgentTool on the selected provider stream, not a worker method, model-Markdown protocol, classifier, or approval dialog. Requests reject unknown properties, malformed options, unknown submitted IDs, and oversized strings. Obsolete pin IDs are unknown IDs and cannot load content or dispatch sibling actions. Runtime code generates option IDs and binds the callback to session, run generation, tool-call ID, and an application-owned question sequence. A model-reused call ID cannot bind an old answer key to a later question. Plain-text labels and validated local previews cannot load model URLs or create live highlights. An explicit answer settles once, continues the same run, and returns `actionApproval: false`.

The full-batch `beforeToolCall` guard discards every sibling when a clarification call is present, even if that question is invalid or appears after a browser/MCP call. Multiple questions and question/sibling ID collisions reject the batch. No discarded call is queued, released by an answer, or automatically replayed. Later independent calls retain exact-origin checks, stale-context checks, permissions, confirmations, and non-replay policy. One pending question and three clarification calls per run are allowed; malformed calls count toward that limit.

Stop, panel close, credential removal in any conversation, and run cancellation release pending callbacks. A pending-only trusted storage listener checks selected-provider presence/type, and an initial credential-metadata read covers removal before registration. Session/run/question identity guards reject late notifications and reads. Settlement removes the listener; no credential payload enters a question, tool result, worker message, or log. A target-context change invalidates the known element IDs and cancels any question linked to them. Later submissions cannot revive or rebind those invalid IDs, including as image attachments. Fresh distinct current-element IDs submitted through explicit steering can support later questions in the same run; image IDs remain valid. The abort/end turn boundary prevents an extra provider request after cancellation. Persistence failure prevents new clarification batches from opening questions; generic persistence-failure behavior is unchanged. History and tree navigation contain inactive question/answer data only and cannot revive callbacks or approvals. See [feature limits and recovery](target-reference.md).

## Page annotation controls

Page drawing is an explicit idle-only user mode, not a model tool or browser mutation approval. The worker binds each five-minute surface to a random token, panel client, exact tab context, and generation. Runtime requests have fixed keys and bounds and require the exact packaged conversation URL, extension ID, and top frame, whether hosted in the Side Panel or an extension tab. Settings and microphone routes are excluded. Injected notifications require the expected extension sender, tab, and top frame. A stroke/revision notification is not authorization to capture or send. Credentials never enter annotation messages or injected execution.

The owned overlay must retain input interception during drawing and direct Chrome capture. Its required 1% black shield tint and marks are visible capture pixels; controls remain outside the tab in the Side Panel. It does not change page-owned content, layout, root styles, dialogs, or popovers. Earlier page capture listeners can still observe events; the overlay is not browser-internal input isolation. Live content can move beneath marks without detection; there is no automatic DOM tracking.

Capture requires exact-site approval, existing optional screenshot `<all_urls>` consent, readability, visible-tab freshness before and after capture, unchanged geometry, and owned frozen painted revision. The direct-capture proof verifies real marked pixels and iframe interception before, during, and after capture. See [acceptance evidence](manual-acceptance.md#page-annotation-acceptance--2026-11-01).

Only six palette IDs and the `pen`, `arrow`, and `rectangle` tool IDs are accepted, not arbitrary CSS or geometry instructions. A legacy start without a tool uses `pen`; invalid IDs and extra request keys fail validation. Width is 2–32 px (default 8), with 256 completed marks, 4,096 points per freehand stroke, and 8,192 points total. A shape consumes one mark and exactly two points. Arrows shorter than 4 CSS pixels and rectangles with either side shorter than 4 CSS pixels are discarded. Coordinates must be finite and viewport-bounded. Canvas limits are 4,096 px per dimension and 16,000,000 pixels. Capture retains the 3,000,000-character screenshot data-URL limit and separate four-image/3,000,000-binary-byte composer limits.

Navigation/reload/SPA context change, tab/window changes, scroll, viewport/zoom changes, expiry, disconnect/restart, access revocation, and protection changes invalidate drawing and pending submission. The pen toggle discards unsent marks. Escape closes an open panel tool popup first; otherwise, Escape cancels drawing. Cleanup is serialized and idempotent; generations reject late capture, permission, and stop replies. Focus restoration requires the owned surface still to hold focus.

One validated PNG is attached before cleanup, and the agent cannot start until cleanup is confirmed. Failed cleanup blocks Send even with a retained image until removal is confirmed. Stop can remove the extension-owned surface from its original tab after a window change or worker restart; it cannot read or capture that stale context. URL/epoch changes and failed tab lookups are not removal evidence. A successful all-tab lookup can confirm a closed target. Capture/attachment failure restores editable marks only in the original safe context. Later submission failure retains the preview and text for manual retry without recapture or duplicate attachment. Only accepted submitted IDs clear. Raw freehand points and shape endpoints are memory-only; sent images remain untrusted provider/transcript data and cannot authorize actions or permission changes. No automatic submission, mutation replay, or remote MCP replay is added. See [page drawing](page-annotation.md).

## Region capture controls

Region capture is an idle-only user workflow, not a model tool or permission grant. It reuses the page-drawing sender boundary: exact packaged conversation URL, extension ID, and top frame. Fixed requests require client and immutable operation UUIDs; the worker owns a random token, generation, original tab context, and five-minute lifetime. Exact keys, finite viewport-bounded rectangles, revisions, and notification sender/frame/token/context checks reject forged or stale data. Notifications cannot authorize capture. A dispatched start with a lost reply still requires confirmed cleanup; a start cancelled before dispatch sends no injection or stop request.

Preview requires image-model support and remaining composer capacity before capture. The worker independently checks exact-site approval, optional screenshot consent, readability, visible context, owned frozen state, rectangle, revision, and geometry before and after native capture and every asynchronous crop boundary. Navigation, window/tab changes, access revocation, protection/viewport changes, expiry, disconnect, and restart invalidate live ownership. Cancellation rejects late full-source and crop results without replay or fallback.

Chrome captures the full viewport temporarily in trusted worker memory. Only `region-crop.ts` decodes that source; no original pixels enter runtime responses, logs, composer, model messages, or stored sessions through this path. Header and decoded dimensions must agree. Source and crop are bounded to 4,096 px per dimension and 16,000,000 pixels, with the existing 3,000,000-character source limit. Ceil left/top and floor right/bottom select inward pixels from actual decoded dimensions. Output must be a non-empty PNG within remaining composer bytes. Decode, encoding, cancellation, or validation failure never returns the original image. Owned bitmaps/canvases and preview URLs are released; secure memory erasure is not claimed.

The shield's 1% tint remains during capture; only its outline is hidden before two paint frames. Existing overlay limitations and input-observation risks still apply. Confirmed cleanup is required before preview attachment, and unconfirmed cleanup blocks both Attach and Send. Only a later explicit Send shares the crop. Text, selected elements, previous messages, and approved browser reads can disclose other content, so the crop is not a general privacy boundary. Static previews contain no live page capability; session restore never restores region ownership. See [region capture and failure recovery](region-capture.md).

## Remote MCP controls

Remote MCP connects from the trusted Side Panel to explicitly configured public HTTPS endpoints. A connection approval binds the complete endpoint, server ID, and revision; Chrome host permission and recorded origin approval are additional checks. Known private/local hostname forms and IP literals are rejected. DNS resolution is not inspected, so public names can still resolve to private addresses. Servers must validate origins and use least-privilege authentication.

MCP tokens use a separate trusted store and authenticate only to the approved endpoint. Requests omit cookies, reject all redirects, and use no provider credentials or OAuth discovery. Configuration/token edits, host permission revocation, run abort, session changes, or panel shutdown invalidate local connections. Unsupported or expired sessions fail without automatically replaying a tool call. Server error text is not exposed; known-token echoes, including JSON-escaped echoes, are rejected before metadata or results leave the client.

Every remote call requires a new confirmation containing its endpoint, tool, and complete bounded arguments, regardless of confirmation mode or server read-only annotations. MCP calls execute sequentially with `replay: "never"`. Server metadata and results cannot grant access, enable tools, or become system instructions. Only bounded text blocks and structured JSON results are accepted; no linked resource is fetched. The JSON Schema subset is interpreted without code generation, reference fetching, or regex execution.

[Remote MCP limits and recovery](mcp.md) define fixed request, response, declaration, schema, pagination, tool-count, and duration limits. A failed or cancelled call can still have changed remote state; the UI reports uncertainty rather than success or an automatic retry. No MCP client or token is passed to the service worker or a web page. Removing a server deletes its token and connection approval; previous session data remains until deleted separately.

## Skill controls

Skill import requires an explicit local-file selection or GitHub fetch/selection, followed by plain-text review. Imported records and explicit replacements start disabled; replacement retains the installed ID. Complete original source, parsed fields, optional license and metadata, and source identity are displayed as text, not executable HTML. A source link opens only on user action. Static warnings cannot identify every unsupported dependency; review the complete source. Text import does not establish full Agent Skills or plugin compatibility.

The shared bundled YAML parser validates UTF-8 and the required name/description plus supported optional fields within the [skill limits](skills.md). It limits YAML to 8 container levels and 256 nodes and rejects tags, anchors, aliases, duplicate keys, multiple documents, and unknown top-level fields. Folded descriptions must normalize to the existing one-line, 512 UTF-16-unit contract; body text is preserved. Optional `allowed-tools` and `compatibility` do not grant tools, access, or execution. No scripts, supporting files, linked resources, plugins, or local directory discovery are available.

GitHub import accepts only validated repository shorthand or an HTTPS `github.com` root URL. The Settings fetch-button gesture requests `https://api.github.com/*`; each request requires both Chrome permission and recorded exact-origin approval through `hasApprovedHostPermission()`. Screenshot `<all_urls>` alone cannot authorize it. Fixed API URLs resolve a default-branch commit and immutable tree, then read only the selected blob. Requests omit cookies and credentials, reject redirects, and do not follow response-supplied URLs. Provider credentials, GitHub tokens, raw-content hosts, archive downloads, and worker bridges are not used.

Streamed response bytes, tree entries, candidate paths, decoded source, and operation duration have [fixed limits](skills.md#github-import). Truncated or oversized listings fail instead of exposing an incomplete list. Rate-limit errors stop without automatic retry. Cancellation, source changes, Settings disposal, and host permission revocation abort pending work; stale results cannot replace a newer review. Discovery, preview, errors, and cancellation do not write or enable records. Import saves the reviewed snapshot without refetching. Source identity and optional fields are review-only; installed records have no persistent provenance or update tracking. Runtime loading makes no network request.

Enabled metadata is serialized as JSON containing only `id`, `name`, and `description`. The body is withheld until the model calls `skills_load({id})`. Both metadata and loaded bodies remain untrusted, user-authorized task guidance, not authority to change system rules, available tools, Chrome permissions, or browser confirmations. A no-page run can load a skill but does not gain page tools from it. Imported text can still influence model behavior; enable only reviewed content that is safe to share with the selected provider.

The runtime snapshots enabled records at run start and validates load IDs against that snapshot. Settings edits apply to the next run, not the active snapshot. Repeated loads count toward the aggregate per-run byte limit. Disable all skills to omit the catalog and loader from later runs. A previous tool result cannot authorize a new load of a disabled or deleted record. Loaded bodies remain in ordinary saved history; disabling, replacement, or deletion does not erase them. Delete affected sessions separately to remove local transcripts; this cannot retract provider-held data.

## Bookmark controls

- Bookmark access is an optional permission and is never requested at install, login, startup, or ordinary prompt submission.
- Every bookmark search or recent-item read requires an operation-specific confirmation or a previously approved exact operation, query, and limit. If Chrome permission is missing, only a fresh Confirm-button gesture can request it. The approval cache never substitutes for the optional Chrome grant.
- The worker rejects bookmark requests carrying a page `TabContext`, rechecks permission before each read, and does not retry after revocation.
- Production code calls only `chrome.bookmarks.search()` and `chrome.bookmarks.getRecent()`; runtime validation exposes no write or whole-tree method, and the artifact audit rejects bookmark mutation calls.
- Confirmation explains that returned bookmark titles and URLs are sent to the selected model provider and saved in the session. An approved matching query may run later without a new dialog in Balanced or Convenient; changing the query or limit asks again. Page-provided content and model output can trigger another matching read, so a reusable approval is not a guarantee of one-time disclosure.
- The permission can be revoked from Chrome's extension settings. Chrome's permission itself covers the broader bookmarks API even though Pi Browser Agent implements reads only.

Bookmark tools declare `replay: "never"` and execute sequentially. A fresh agent request may use a matching approval, but an interrupted tool call is never replayed automatically.

## Untrusted content and limits

Visible page text, selection, selected-element context, screenshot metadata, tab metadata, bookmark data, and WebMCP results are wrapped as untrusted content before model use. They cannot enter the system-prompt channel. Visible text and selections are truncated to 50 KB. Screenshots require the optional broad Chrome grant, are limited by runtime checks to the current visible HTTP(S) viewport, and are rejected above 3 MB. The completed-screenshot editor accepts only a validated PNG header and matching decoded dimensions, rejects sources above 16,384 px per side or 64 million pixels, downscales editing to at most 4,096 px per side and 16 million pixels, and bounds stroke/point counts and pen width. Export must be a non-empty PNG of at most 3 MB and is revalidated against the existing four-image/3 MB composer limits. Editing is local, the original result is immutable, and cancel/`Esc` stores and sends nothing. Clipboard input accepts at most four PNG, JPEG, WebP, or GIF images using 3 MB in total; SVG and other MIME types are rejected, and transcript rendering constructs data URLs only for validated raster-image content. Bookmark search requires a non-empty query, and search and recent reads are capped at 50 normalized nodes and 50 KB. Voice input uses Chrome's Web Speech service and may send audio to the browser's configured speech provider; Pi Browser Agent receives an editable transcript and does not submit it to the model until the user sends the message. Session records are rejected above 5 MB and retention is capped at 50 sessions.

## Conversation branch controls

`/tree` is a local UI action, not a model tool. Opening, canceling, or selecting a node requests no provider/site permission and starts no model or tool execution. Only the selected path enters a later explicit prompt. Other branches remain in trusted IndexedDB storage; switching paths does not undo browser or remote-server side effects.

Tree validation requires bounded nodes, unique IDs, earlier valid parents, a valid active leaf, supported message structure, and an exact active transcript projection. Labels are bounded plain text; HTML, links, image loading, and page instructions are not activated by the tree. Unresolved or invalid tool-call/result prefixes cannot become new continuation boundaries. Historical tool results remain data and cannot restore a live element reference or approval.

Selection requires an idle, auth-stable, owned session and is rechecked before the atomic write. Drafts and attachments cannot be silently replaced. Restored slash-prefixed user text is escaped in the composer so Send resubmits model text instead of invoking a local command. Restored images use the existing composer MIME/count/byte limits. Local mutations are locked during the transaction. Shutdown and credential removal wait for navigation to settle before final persistence or lease release. A failed transaction retains the previous saved context. Tree records are never automatically pruned to fit the storage limit; oversized saves report failure instead. Older builds do not preserve inactive branches when writing, so retain complete records before downgrade.

## Transcript rendering

Assistant Markdown is untrusted. Bundled Marked escapes raw HTML and suppresses image rendering; DOMPurify permits only presentation tags and necessary attributes. A separate URL check rejects non-HTTP(S), relative, and credential-bearing links. Allowed links open only on user clicks with `noopener noreferrer`. Script, SVG, MathML, forms, embeds, event handlers, inline styles, and passive remote resources are excluded. Sanitization also applies to incomplete streams and restored transcripts. Existing validated raster-image message blocks remain on their separate data-URL path.

User messages, thinking, and tool payloads remain plain text. Copy controls invoke the Clipboard API only from a user gesture and report failures without requesting new permissions. Rendered HTML, disclosure state, and DOM node registries are not persisted or sent to models. Saved discovery results cannot restore a live reference registry.

## Build boundary

The production build includes `pi-agent-core`, browser-compatible built-in `pi-ai` provider code, and browser-owned Codex OAuth. It excludes Amazon Bedrock's Node-only adapter, native processes, shell tools, filesystem discovery, dynamic remote code, and Node OAuth callback modules. The browser-boundary probe bundles all registered providers and their lazy API paths. `npm run audit:artifact` parses emitted JavaScript and rejects executable Node built-in imports while ignoring documentation strings, and also rejects loopback transport URLs, remote scripts, source maps, embedded credential patterns, bookmark mutation calls, and unexpected required, optional, or host permissions. It also requires screenshot access to remain declared as optional `<all_urls>` and rejects every required host permission.

On 2026-09-21, `npm audit --omit=dev` and `npm audit` both reported zero vulnerabilities. Markdown dependencies are pinned to Marked 18.0.13 and DOMPurify 3.4.15 in the lockfile and bundled locally; no parser or sanitizer code is fetched at runtime.

## Residual risks

- Provider APIs and catalogs can change independently of this extension, and an endpoint may decline extension-origin requests even after Chrome grants host access.
- The complete static model catalog and bundled MCP SDK increase the packaged Side Panel size.
- A configured MCP server receives its token and confirmed arguments and can retain or misuse them. Browser hostname validation cannot prevent DNS rebinding. Dedicated tokens and server-side origin validation remain necessary.
- Browser-profile credential storage is less protected than an OS keychain.
- Browser or panel termination can interrupt a stream; the last complete transcript remains recoverable, but partial content is not treated as complete.
- Page confirmation describes an intended action, but the page can still change between inspection and execution. Link targets are rechecked immediately before controlled navigation.
- Element-picker selectors can become stale or match a different node after DOM changes. They are descriptive context only, not authorization to mutate.
- A normal page overlay cannot suppress an event already observed by an earlier page-level capture listener, although the selected target and its default activation remain blocked.
