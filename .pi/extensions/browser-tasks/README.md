# Local Browser tasks for Pi

This optional project-local plugin keeps Pi in WSL and attaches to **existing Windows Chrome and its existing profile**. It launches only a helper with installed Windows Bun through WSL interop, not a browser. It creates or copies no profile or credentials.

The helper reads at most 1,024 bytes of `%LOCALAPPDATA%/Google/Chrome/User Data/DevToolsActivePort` metadata and uses a native Windows WebSocket to Chrome's user-enabled loopback CDP endpoint. No project server, port forwarding, Native Messaging registration, external relay, endpoint URL/token input, or feature environment flag is used. CDP grants broad personal-profile authority; the narrow task adapter is not a sandbox against a malicious Pi environment.

1. Use already-running Windows Chrome 144 or newer and an installed Windows Bun available on the Windows PATH. Bun is discovered through a fixed PowerShell query, never installed automatically. No new Chromium or profile is needed.
2. From the repository root, run `npm ci` and `npm run build`. Load `dist/chrome` in existing Windows Chrome or select the existing extension's **Reload** action at `chrome://extensions`. Copy its public 32-letter `a`–`p` extension ID.
3. Enable remote debugging yourself at `chrome://inspect/#remote-debugging`. Do not restart normal Chrome with legacy debugging-port flags or weaken browser security.
4. Start Pi Coding Agent 1.5.0 from this root and approve project trust. If Pi is already open, use `/reload`. While idle with no pending messages, run `/browser-connect` without arguments, enter the public extension ID once, and confirm existing-profile trust and automatic task execution. The ID is saved in `<getAgentDir()>/pi-browser-agent.json`, normally `~/.pi/agent/pi-browser-agent.json`, and reused on later connections. Edit that file to change the ID; it stores no credentials or connection consent.
5. Approve Chrome's native connection prompt yourself. In **Settings → Tools → Local Coding Agent connection**, select the real **Allow local connection** button and confirm. This gesture opens the real conversation Side Panel; keep it open. The helper may create only the pinned Settings tab and leaves other tabs open.
6. Use the Browser credentials already in that profile or configure them through Browser's normal dialogs. Pi's `browser_task` starts automatically when Browser is ready and idle with an empty composer. No additional Pi task confirmation or Browser **Send** is required. Missing provider/site access uses an explicit permission confirmation. Native permissions and browser-action confirmations remain required.

Reload both Pi and Chrome after this update, then approve a new connection. API version 2 and session-storage key `piBrowserAgentLocalCodingSessionV2` require new consent; old draft-only approval is not migrated.

`browser_task` submits once and waits with read-only polling. `browser_task_status` inspects a tracked task; `browser_task_cancel` confirms cancellation. Browser's freshly confirmed `coding_task` requires explicit `/browser-inbox`, `/browser-accept <task-id>`, and `browser_task_reply` with exact-answer confirmation. Neither direction exports a transcript, thinking, HTML, attachments, or credentials. Known stored provider values are redacted from outgoing Browser task text and selected answers. Neither agent delegates back while handling a peer task.

`/browser-disconnect`, Pi shutdown, reload, and session replacement attempt to revoke only their own pending or approved connection, detach their own CDP sessions, and close their WebSocket and helper. They never close Chrome or its tabs, terminate Chrome, or remove its profile. Failed or abrupt loss can leave stale approval or in-flight work: inspect and stop Browser work and revoke stale approval in Settings before connecting again. No automatic reconnect or replay occurs. Task handles are memory-only; cancellation cannot undo earlier effects or prove all actions stopped.

The ignored legacy `.pi/browser-profile/` may contain private data. Current code does not create, use, delete, or migrate it. Production browser code remains browser-only; helper/process/CDP code is outside the artifact under `.pi/`. Local refers only to inter-agent transport, not offline model requests, browsing, or remote MCP.

An explicitly owner-authorized live WSL-to-Windows task test passed with Windows Chrome 156.0.8078.79, Windows Bun 1.3.14, the actual helper, and the typed task client. A new empty conversation returned the exact expected model reply; the diagnostic requested no web-page operation and detached without closing Chrome or its tabs. Its authorized UI diagnostic was separate from the production adapter and tested the earlier manual-Send workflow. Full CI for that earlier workflow passed 2,575 unit/integration and 343 E2E tests, both typechecks, build, and artifact audit. Live Browser-to-Coding and personal-profile lifecycle checks remain owner work. The temporary diagnostic client does not enroll the running Pi plugin; use `/reload`, then `/browser-connect` for that session.
